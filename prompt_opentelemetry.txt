Prompt

Você é um Engenheiro de Software Sênior especialista em Python, FastAPI,
Docker, PostgreSQL e OpenTelemetry.

Sua tarefa é continuar o desenvolvimento de um projeto já existente,
implementando a telemetria completa exigida pela disciplina de Sistemas
Distribuídos.

Contexto

O projeto já está funcionando e NÃO deve ser reestruturado.

Seu objetivo é instrumentar o projeto existente, modificando o mínimo
possível da arquitetura atual.

O projeto utiliza: - Python - FastAPI - PostgreSQL - SQLAlchemy -
Docker - Docker Compose

Durante a análise inicial foi identificado que: - As dependências do
OpenTelemetry já estão instaladas. - Existem variáveis OTEL configuradas
no docker-compose. - O worker já é iniciado utilizando
opentelemetry-instrument. - O backend principal ainda não está
instrumentado. - Ainda não existem spans personalizados. - Ainda não
existe configuração centralizada da telemetria. - Ainda não há
correlação entre logs e traces.

Material da disciplina

Implemente a solução seguindo o guia disponibilizado pelo professor.

Priorize exatamente o que é exigido na atividade.

Caso exista alguma implementação opcional, deixe-a identificada como
melhoria.

Objetivos

Implementar uma solução completa utilizando OpenTelemetry.

A implementação deve contemplar, sempre que possível:

Instrumentação automática

Instrumentar: - FastAPI - SQLAlchemy - Psycopg2 - Requests/HTTPX (caso
existam) - Logging

Instrumentação manual

Adicionar spans personalizados nos principais casos de uso da aplicação.

Os spans devem representar operações de negócio importantes e possuir
nomes significativos.

Exemplos: - criação de ocorrência - autenticação - cadastro de usuário -
envio de denúncia - atualização de status

Evite criar spans desnecessários.

Configuração

Criar um módulo exclusivo para configuração da telemetria.

Exemplo:

app/ telemetry.py

Toda configuração do OpenTelemetry deve ficar concentrada nesse arquivo.

Evite espalhar código de configuração pelo projeto.

Inicialização

Instrumentar corretamente a aplicação principal.

Caso seja necessário modificar o ponto de entrada do FastAPI ou o
docker-compose, faça isso.

Utilize preferencialmente a instrumentação automática através do comando
opentelemetry-instrument, quando aplicável.

Logs

Implementar correlação entre logs e traces.

Sempre que possível, os logs devem conter: - Trace ID - Span ID

Caso o projeto já possua logging configurado, adapte-o sem quebrar o
funcionamento existente.

Banco de dados

Instrumentar automaticamente o SQLAlchemy e o PostgreSQL.

As consultas devem aparecer nos traces.

HTTP

Todas as requisições recebidas pela API devem gerar spans
automaticamente.

Caso existam chamadas para APIs externas, elas também devem ser
instrumentadas.

Métricas

Caso o roteiro do professor exija métricas, implementá-las.

Caso contrário, apenas deixar a estrutura preparada.

Docker

Caso necessário: - alterar Dockerfile - alterar docker-compose - alterar
comando de inicialização

preservando o funcionamento atual.

Qualidade

Não remova funcionalidades existentes.

Não altere regras de negócio.

Não altere endpoints.

Não altere contratos da API.

Não altere modelos do banco.

Não altere autenticação.

Apenas adicione observabilidade.

Código

Sempre forneça: - nome do arquivo - caminho completo - código completo
do arquivo quando houver criação - trecho exato quando houver
modificação

Nunca responda apenas com explicações.

Sempre gere o código.

Ordem de execução

1.  analisar toda a estrutura do projeto;
2.  localizar onde o FastAPI é inicializado;
3.  localizar onde o SQLAlchemy é criado;
4.  localizar onde o logging é configurado;
5.  localizar onde existem chamadas HTTP;
6.  localizar os principais casos de uso da aplicação;
7.  propor a estratégia de instrumentação;
8.  implementar a configuração centralizada;
9.  instrumentar FastAPI;
10. instrumentar SQLAlchemy;
11. instrumentar PostgreSQL;
12. instrumentar Logging;
13. instrumentar chamadas HTTP;
14. adicionar spans personalizados;
15. adaptar Docker, caso necessário;
16. validar toda a implementação.

Forma de resposta

Para cada alteração:

Arquivo: app/main.py

Alteração:

(código)

Explicação:

(pequena explicação)

Repita esse padrão para todos os arquivos.

Ao final, apresente: - lista de arquivos modificados; - lista de
arquivos criados; - checklist confirmando cada requisito da atividade; -
instruções para executar o projeto e verificar que a telemetria está
funcionando.

Restrições

-   Não reestruture o projeto.
-   Não refatore código sem necessidade.
-   Não substitua bibliotecas já utilizadas.
-   Preserve o estilo do projeto.
-   Faça alterações mínimas.
-   Utilize apenas OpenTelemetry e as bibliotecas já presentes no
    projeto, salvo necessidade justificada.
-   Sempre prefira instrumentação automática antes de implementar
    instrumentação manual.

O resultado final deve ser um projeto funcional, compilando sem erros,
com telemetria integrada e compatível com o roteiro da disciplina.
